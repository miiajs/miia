title: CLI
description: Create projects, add features, generate code, and run the dev server, build and production start.
status: beta
---

`@miiajs/cli` creates MiiaJS projects (`miia new`, or `bun create miia`), adds features to them (`miia add`), generates modules, controllers, services and CRUD resources (`miia g`), and runs them on Bun, Node.js and Deno (`miia dev`, `build`, `start`, `check`).

## Create a project

::code-group

```bash [bun]
bun create miia my-app
```

```bash [npm]
npm create miia@latest my-app
```

```bash [pnpm]
pnpm create miia my-app
```

```bash [yarn]
yarn create miia my-app
```

```bash [deno]
deno run -A npm:create-miia my-app
```

::

`create-miia` is a thin package that runs `miia new` with the same arguments; `bunx @miiajs/cli new my-app` does the same. The generated project lists `@miiajs/cli` as a devDependency, so its scripts call `miia` directly. Outside the scripts, run the project's own binary with `bunx miia ...` or `npx miia ...`; a project created with `--pm deno` gets a `miia` task for that, `deno task miia ...`, so it runs the project's CLI version rather than the latest from npm.

## `miia new`

```bash
bun create miia my-app
bun create miia my-app --runtime node --pm pnpm --features jwt-auth,swagger --db drizzle-postgres
bun create miia my-app -y            # defaults, no prompts
bun create miia .                    # in the current, empty folder
```

npm keeps flags before `--` for itself: `npm create miia@latest my-app -- --runtime node -y`.

In a terminal the CLI asks for whatever the flags leave open: name, runtime, package manager (Node.js only), features and database. With `-y`, or without a terminal (CI, scripts), nothing is asked and the defaults apply; the name is then required.

| Flag | Default | Description |
| --- | --- | --- |
| `[name]` | prompt | npm package name (lower case, `@scope/name` allowed); the folder is its last segment. `.` uses the current folder and its name |
| `--runtime`, `-r` | `bun` if installed, else `node` | `bun`, `node`, `deno` |
| `--pm` | `bun` for Bun, `deno` for Deno; for Node.js the package manager that runs the command (`npm create` -> npm, `pnpm create` -> pnpm), else npm | `bun`, `npm`, `pnpm`, `yarn`, `deno` |
| `--features` | none | Comma-separated add-ons, see [`miia add`](#miia-add) |
| `--db` | `none` | One database add-on |
| `--yes`, `-y` | `false` | No prompts |
| `--skip-install` | `false` | Write the files, skip the install |
| `--dry-run` | `false` | Print the files and dependencies without writing anything |

The folder must not exist or be empty. Nothing is written until every step has succeeded; a failed install leaves the files in place and says which command to run.

### What you get

```
my-app/
├── .env               # your local values, git-ignored
├── .env.example       # every variable; secrets left empty
├── .gitignore
├── README.md
├── package.json
├── tsconfig.json
└── src/
    ├── main.ts
    ├── env.schema.ts
    └── app/
        ├── app.module.ts
        ├── app.controller.ts
        ├── app.service.ts
        └── app.test.ts
```

The project is laid out for strict module boundaries: `ConfigModule` is configured `{ global: true }` and validates `src/env.schema.ts` (`NODE_ENV`, `HOST`, `PORT`), and `main.ts` reads the port and host through a typed `ConfigService`:

```ts [src/main.ts]
import { ConfigService } from '@miiajs/config'
import { Miia } from '@miiajs/core'
import { AppModule } from './app/app.module.js'
import type { Env } from './env.schema.js'

const app = new Miia().register(AppModule)
const config = app.get<ConfigService<Env>>(ConfigService)

await app.listen(config.get('PORT'), config.get('HOST'))
```

Per runtime:

| Runtime | Differences | `test` script |
| --- | --- | --- |
| Bun | `@types/bun` | `bun test` |
| Node.js | `@miiajs/node-server` (`serve` passed to `listen`), `tsx`, `tsconfig.build.json` for `miia build` | `node --import tsx --test "src/**/*.test.ts"` |
| Deno | `deno.json` with `"unstable": ["sloppy-imports"]` (the `.js` specifiers point at `.ts` files) | `deno test --no-check --allow-all src/` |

Every script pins the runtime (`miia dev --runtime bun`), so the project does not depend on runtime detection. The scripts are `dev`, `build`, `start`, `check` and `test`.

Tests sit next to the code (`src/**/*.test.ts`) and test their own module through `TestApp`, not the whole `AppModule`, so they pass without `.env` or a database. They are written for `bun:test`; on Node.js and Deno the import becomes `node:test` plus the [`expect`](https://www.npmjs.com/package/expect) package, which has the same API. Each test creates and closes its own `TestApp`: `node:test` on Deno has no `before`/`after` hooks.

## `miia add`

Adds features to an existing project. `miia new --features ... --db ...` applies the same add-ons the same way.

```bash
bunx miia add jwt-auth swagger
bunx miia add drizzle-sqlite --dry-run
bunx miia add                        # pick from a list (in a terminal)
```

| Add-on | What it adds | Runtimes |
| --- | --- | --- |
| `jwt-auth` | `@miiajs/auth` + `@miiajs/jwt`: a global `AuthModule` (exports `JwtAuth`) with `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, the `LocalAuth` and `JwtAuth` providers, an in-memory `UsersService` in `src/users/`, `ctx.user` typing in `src/types/core.d.ts`, `JWT_SECRET` (a random value in `.env`, empty in `.env.example`, so a copied example does not start with a known secret) and a test. Passwords use `Bun.password` on Bun and `scrypt` from `node:crypto` elsewhere | all |
| `swagger` | `SwaggerModule`: the spec at `/docs/json`, the UI at `/docs` | all |
| `cors` | `app.use(cors({ origin: config.get('CORS_ORIGIN') }))` in `main.ts`, `CORS_ORIGIN` (default `*`) | all |
| `serve-static` | `serveStatic(app, '/static', './public')` and `public/index.html` | all |
| `rate-limit` | `RateLimitModule` (100 requests a minute per client) and the global `RateLimitGuard` | all |
| `biome` | `biome.json`, `format` and `lint` scripts; generated files are formatted from then on | all |
| `drizzle-postgres` | `DrizzleModule` with `postgres`, `src/db/schema.ts` (a `notes` table), `src/db/db.ts` (the typed `drizzleDb()` handle), `drizzle.config.ts`, `db:generate` and `db:migrate`, `DATABASE_URL` | all |
| `drizzle-mysql` | The same with `mysql2` | all |
| `drizzle-sqlite` | The same on `bun:sqlite` (Bun; `db:migrate` runs `src/db/migrate.ts`) or `better-sqlite3` (Node.js). `data.db` is git-ignored | Bun, Node.js |
| `papr` | `PaprModule` with `papr` and `mongodb`, `MONGODB_URL` | all |
| `mongoose` | `MongooseModule` with `mongoose`, `MONGODB_URL` | all |

Modules that the rest of the app injects from (JWT, rate limit, databases) are registered `{ global: true }` in the root module, and their factories read config as `resolve<ConfigService<Env>>(ConfigService).getOrThrow('JWT_SECRET')`. A project has one database add-on: adding a second one is refused.

What `miia add` does:

- **Finds the files to edit:** the root module (`src/app/app.module.ts`, or the module `src/main.ts` registers), `src/main.ts` (statements go before `app.listen()`), the env schema (`src/env.schema.ts`, or the first `src/**/env.schema.ts`), `.env.example` and `.env`. The runtime comes from `--runtime` in the `dev` script, else from [detection](#runtime-detection); the package manager from the lockfile.
- **Edits code in place.** Imports and module entries are inserted at the right spot through the TypeScript compiler API; the rest of each file stays byte for byte, line endings and indentation included. When it cannot edit something safely (`imports` held in a variable, a spread, a `bootstrap()` function around `listen`, no `ConfigModule`), it prints what to add by hand instead of guessing.
- **Skips what is installed.** `swagger is already installed`; running the same `miia add` twice changes nothing.
- **Refuses conflicting files.** `jwt-auth` creates `src/users/*` and `src/types/core.d.ts`. If such a file exists with other content (for example after `miia g resource users`), the command lists every conflict and writes nothing.
- **Checks git first.** On a dirty working tree it warns and, in a terminal, asks before going on (`-y` skips the question).
- **Installs and formats.** After writing, it runs the install when dependencies changed (`--skip-install` to skip) and formats the changed files with the project's formatter.

| Flag | Default | Description |
| --- | --- | --- |
| `[add-ons...]` | prompt in a terminal, error without one | Add-on ids |
| `--yes`, `-y` | `false` | Do not ask about a dirty git tree |
| `--skip-install` | `false` | Skip the install |
| `--dry-run` | `false` | Print the changed files and new dependencies without writing |

## `miia generate`

Generates artifacts inside a project. Alias: `miia g`.

```bash
bunx miia g resource posts
bunx miia g service audit --export
bunx miia g c admin/users
```

```
  UPDATE src/app/app.module.ts
  CREATE src/posts/posts.controller.ts
  CREATE src/posts/posts.module.ts
  CREATE src/posts/posts.schemas.ts
  CREATE src/posts/posts.service.ts
  CREATE src/posts/posts.test.ts
```

| Schematic | Alias | Generates | Registered in the parent module |
| --- | --- | --- | --- |
| `module` | `m` | `@Module` class | `imports` |
| `controller` | `c` | `@Controller` with `GET /` | `controllers` |
| `service` | `s` | `@Injectable` class | `providers`; also `exports` with `--export` |
| `resource` | `r` | Module, controller, service, schemas and a test | `imports`; the resource module exports its service |
| `guard` | - | `CanActivate` class | nowhere: a guard no module declares is built for the controller that uses it, so it works from any module |
| `middleware` | - | `Middleware` function | nowhere: use it with `app.use()` or `@Use()` |

**Resource.** A working CRUD module: zod route schemas (`Create<Name>Schema`, `Update<Name>Schema`, `<Name>IdParamsSchema` with a numeric `id`), `POST` with `@Status(201)`, `GET`, `GET :id`, `PATCH :id`, `DELETE :id` with `@Status(204)`, `NotFoundException` for a missing id, a service on a `Map` to replace with your database, and a `TestApp` test covering 201, 404, 422 and 204. `check` and `test` pass right after generation.

**Names.** Letters, digits, `-` and `_`, starting with a letter; `/` separates folders. Classes are PascalCase and files kebab-case, acronyms included: `HTTPServer` becomes `HttpServerService` in `http-server.service.ts`. A dot or any other character is an error.

**Placement.** By default `src/<name>/<name>.<kind>.ts`. `--flat` drops the folder, a name with a path (`admin/users`) uses that folder as is, and `--path core` puts everything under `src/core/`. A resource always gets its own folder. An existing file stops the command before anything is written.

**Parent module.** The CLI walks up from the target folder toward `src/` and takes the nearest `*.module.ts` (the one named after the folder when there are several), falling back to `src/app/app.module.ts`. Registration adds the import and the array entry and keeps the rest of the file as it was. Without a parent module, or with a shape it cannot edit, the files are still created and you get a warning to register the class yourself.

**Formatting.** New and changed files go through the project's formatter: `biome.json` / `biome.jsonc` -> `node_modules/.bin/biome`, `.prettierrc*` / `prettier.config.js` -> `node_modules/.bin/prettier`. Only the project's own binaries are used; a formatter that fails prints one warning.

| Flag | Default | Description |
| --- | --- | --- |
| `--path` | - | Folder under `src/` |
| `--flat` | `false` | No folder for the artifact |
| `--export` | `false` | `service` only: also add it to `exports` |
| `--dry-run` | `false` | Print the changes without writing |

Without a schematic or a name the command asks for them in a terminal and prints the usage otherwise.

## `miia dev`, `build`, `start`, `check`

### `miia dev`

Runs the runtime's own watcher and `tsc --noEmit --watch` side by side:

| Runtime | Server |
| --- | --- |
| Bun | `bun --watch src/main.ts` |
| Deno | `deno run --allow-all --sloppy-imports --watch src/main.ts` |
| Node.js | `node --import tsx --watch src/main.ts` |

When the app crashes, the watcher waits for the next file change; when `tsc` stops, the CLI prints a warning and the server keeps running. `NODE_ENV` is `development` unless you set it. On Linux and macOS the watcher runs in its own process group, so stopping `dev` also stops the app that `node --watch` runs as a separate process.

### `miia build`

| Runtime | Runs |
| --- | --- |
| Bun / Deno | `tsc --noEmit` (the runtime executes TypeScript directly) |
| Node.js | `tsc -p tsconfig.build.json` when the file exists (generated projects have it; tests are left out of `dist/`), else `tsc`. A config with `"noEmit": true` is refused: it would build nothing for `miia start` |

### `miia start`

| Runtime | Runs |
| --- | --- |
| Bun | `bun src/main.ts` |
| Deno | `deno run --allow-all --sloppy-imports src/main.ts` |
| Node.js | `node --enable-source-maps dist/main.js` |

`NODE_ENV` is `production` unless you set it. `start` does not need `tsc`, so a production image can leave TypeScript out.

### `miia check`

`tsc --noEmit`. No flags.

### Flags

| Flag | Commands | Default | Description |
| --- | --- | --- | --- |
| `--runtime`, `-r` | dev, build, start | [detected](#runtime-detection) | `bun`, `deno`, `node` |
| `--entry` | dev, start | `src/main.ts` | Entry file |
| `--dist` | start | `dist/main.js` | Compiled entry (Node.js) |
| `--env-file` | dev, start | `.env` when it exists | Passed to the runtime as `--env-file` |

`tsc` is the project's own (`node_modules/.bin`, walking up), else the one in `PATH`.

### Exit codes and signals

- `start` and `dev` exit with the code the app exited with, so 0 after a clean shutdown on Ctrl+C or `SIGTERM`. When a signal ended the app, the code is `128 + signal`: 143 for an app with no `SIGTERM` handler, 137 after `SIGKILL`.
- The first `SIGINT`, `SIGTERM` or `SIGHUP` is forwarded to the app as `SIGTERM`, and the CLI waits for the app's graceful shutdown however long it takes. A repeat within a second is ignored: Ctrl+C under `bun run` or `npm run` delivers two. A signal after that kills the app (`SIGKILL`). `dev` also kills anything still running 10 seconds after the first signal.
- A command that fails (a missing runtime, `tsc` not installed, an invalid flag) prints one line and exits with 1.

## Runtime detection

`dev`, `build`, `start` and `miia add` pick the runtime in this order:

1. `--runtime`.
2. Walking up from the current folder, on each level: `deno.json` / `deno.jsonc` -> Deno; then a lockfile: `bun.lock` / `bun.lockb` -> Bun, `deno.lock` -> Deno, `package-lock.json` / `yarn.lock` / `pnpm-lock.yaml` -> Node.js. The first level with a match wins, so a Deno project installed with pnpm still runs on Deno, and a package in a monorepo finds the lockfile at the root.
3. `bun`, then `deno` in `PATH`.
4. Node.js.

## Versions

`@miiajs/*` packages in a generated project get `^` of the CLI version: the CLI and every `@miiajs/*` package release together at one version. Third-party versions live in the CLI's templates, and a test checks them against the peer ranges of the `@miiajs/*` packages and that every required peer (`jose`, `swagger-ui-dist`, `drizzle-orm`, ...) is there.

## Prerequisites

| Tool | Needed for |
| --- | --- |
| `typescript` 6 | A peer dependency of the CLI: `new`, `add` and `g` edit files through its compiler API; `dev`, `build` and `check` run `tsc`. Generated projects have it |
| `tsx` | `miia dev` on Node.js. Generated Node.js projects have it |
| `bun` / `deno` / `node` | The runtime you run on. Deno 2.4 or newer |

Windows is handled in code (executables found through `PATHEXT`, including `.cmd` shims; CRLF files keep their line endings), but the end-to-end run that generates and starts projects runs on macOS and Linux only.
