MiiaJS writes its own messages - mapped routes at startup, the listening address, shutdown, and unhandled errors - through one logger. By default that is `ConsoleLogger`, a colored text format on the console. You can configure it, switch it off, or replace it with your own implementation.

## Default output

Each line carries the app name, the process ID, a timestamp, the level, the context the message comes from, and the time since the previous line:

```text
[Miia] 48213 2026-10-22 10:23:20.123 AM LOG   [Router] Mapped {/users, GET} route +2ms
[Miia] 48213 2026-10-22 10:23:20.131 AM LOG   [App] Listening on http://0.0.0.0:3000 +8ms
```

Errors go to `console.error`, warnings to `console.warn`, everything else to `console.log`. An error thrown by a handler that is neither an `HttpException` nor a body-size error is logged with its stack under the `RequestHandler` context, and the client gets a `500`.

## Options

Pass a `LoggerConfig` as the `logger` option to configure the built-in logger:

```typescript
import { LogLevel, Miia } from '@miiajs/core'

const app = new Miia({
  logger: { level: LogLevel.DEBUG, appName: 'orders', colors: false },
})
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `level` | `LogLevel` | `LogLevel.LOG` | Most verbose level written: `ERROR`, `WARN`, `LOG` or `DEBUG`. The default drops debug messages |
| `json` | `boolean` | `false` | One JSON object per line instead of the text format |
| `appName` | `string` | `'Miia'` | The name at the start of each line, `app` in JSON |
| `colors` | `boolean` | on, unless `NO_COLOR` is set | ANSI colors in the text format |

With `json: true` each line is an object with `app`, `level`, `message`, `context`, `timestamp` (ISO 8601) and `pid`, plus `trace` for an error that has one:

```json
{"app":"Miia","level":"LOG","message":"Mapped {/users, GET} route","context":"Router","timestamp":"2026-10-22T08:23:20.123Z","pid":48213}
```

### Colors and NO_COLOR

Colors are on by default. When the [`NO_COLOR`](https://no-color.org) environment variable is set to anything but an empty string, the text format has no escape codes, so logs written to a file or collected by `docker logs` stay clean. On Deno the setting is read from `Deno.noColor`, which needs no `--allow-env`. An explicit `colors` option wins over `NO_COLOR` either way.

## Disabling the logger

`logger: false` silences every message, the ones from packages included:

```typescript
const app = new Miia({ logger: false })
```

`TestApp` from `@miiajs/testing` builds its app this way, so tests run quietly. Logging comes back on `close()`, or when `compile()` throws.

## Logging from your code

The `Logger` class writes through whatever logger the app installed. Give it a context, and every message carries it:

```typescript
import { Injectable, Logger } from '@miiajs/core'

@Injectable()
export class OrdersService {
  private logger = new Logger('OrdersService')

  async place(id: string) {
    this.logger.log(`Placing order ${id}`)
    this.logger.debug('Payload validated')
  }
}
```

Packages do the same: the database integrations, the message bus and the Redis transport log under their own context names.

## A custom logger

Anything that implements `LoggerService` can stand in for the built-in logger - pass the instance as the `logger` option:

```typescript
import pino from 'pino'
import { Miia, type LoggerService } from '@miiajs/core'

const log = pino()

const logger: LoggerService = {
  log: (message, context) => log.info({ context }, message),
  warn: (message, context) => log.warn({ context }, message),
  error: (message, trace, context) => log.error({ context, trace }, message),
  debug: (message, context) => log.debug({ context }, message),
}

const app = new Miia({ logger })
```

```typescript
interface LoggerService {
  log(message: string, context?: string): void
  error(message: string, trace?: string, context?: string): void
  warn(message: string, context?: string): void
  debug?(message: string, context?: string): void
}
```

`debug` is optional; without it debug messages are dropped.

::note
The logger is process-wide. `new Miia({ logger })` installs it for every `Logger` in the process - another app's and the packages' included - and `app.destroy()` puts back the one that was there before, unless something has replaced it since. Without a `logger` option an app leaves the current one in place.
::

The [server adapters](/docs/packages/node-server) take a `logger` option of their own for the errors they catch outside the app; `app.listen(port, serve)` passes the app's logger to them.
